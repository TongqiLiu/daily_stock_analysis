存量 `win_rate_pct=34.11%` 的分子是方向判断的 `win`，分母是 `win+loss`，排除了 `neutral`，且包括观望等现金建议。它不是 433 次模拟做多的盈利比例，更不是某一个技能的胜率。正收益比例超过一半仍可能均值为负：本次存量数据中平均亏损大于平均盈利。不能通过单独提高“命中率”或删除亏损样本解决这个问题。

## 当前代码的只读重放

审计脚本使用现有起点解析器、日线窗口解析器与 `BacktestEngine.evaluate_single`，不拉取新行情、不生成新信号、不覆盖原记录。当前配置中性区间为 2%。对全部 1,958 条存量逐条重放的结果：

| 当前可完成 / 当前不足以评估 | 892 / 1,066 |
| 已比对字段一致 / 至少一项变化 | 796 / 1,162 |
| 评估状态变化 | 901 |
| 起始价格变化 | 392 |
| 标的收益变化 | 399 |
| 模拟收益变化 | 191 |
| 方向结果变化 | 177 |
| 缺少或不合格的市场相位上下文 | 1,065 |
| 有效日线日期晚于分析日期 | 1 |

各“变化”项可以在同一条记录发生，不能相加。对于当前不足记录，只比较状态，不将其缺失收益与旧收益作数值比较。当前完成集合中有 133 条模拟做多，平均模拟收益为 -0.4701%，同样未扣费用；这与旧 433 条做多并非相同样本集，不能解释成新技能的收益变化。

旧记录有的仅保留 `enhanced_context.date`、`today.date` 和无时区的 `created_at`，没有可靠的盘前/盘中/盘后相位。仅凭这些字段无法恢复信号实际可见时点，不能补一个假相位来提高覆盖率。保留不足状态及原因；若未来有原始带时区任务日志、行情源时间和完整快照，应单独核验修复来源后，在新评估版本中重跑。

`v1` 是存储标签，不是完整实现及数据版本的证明。日历/起点规则、历史数据更新、历史分析字段变化都可能使同名标签的结果不可复现。该审计比较定位差异，不能仅凭差异计数断言每条变化的唯一根因。

## 工具现在怎样提供证据

- `get_stock_backtest_summary(stock_code)` 和 `get_strategy_backtest_summary()` 省略窗口时使用最新已有汇总的周期，返回 `requested_eval_window_days`、`effective_eval_window_days`、`window_selection` 与 `available_eval_window_days`。没有汇总但有明细时，明确选择最短已有周期；同次明细不会混用多个周期。
- 明确请求 30 日，而只有 10 日记录时，保持 30 日并报告缺失，不静默替换。
- `evidence_profile` 从实际明细只读聚合，包括覆盖日期、状态分母、做多收益分母、盈利/亏损幅度和均值。零样本的比例/均值为 `null`，不填 0 或 50%。
- 问股已确认的标的身份贯穿汇总、可用周期、证据画像和逐笔明细，不能只约束汇总而让其他查询混入同码异市场数据。旧调用保持原接口兼容；指数不借用同码个股回测。
- 旧汇总字段保持兼容；`win_rate_pct` 仍是方向结果比例。交易盈利另看 `profitable_long_rate_pct` 及 `long_return_count`，收益看 `avg_long_simulated_return_pct`，同时核对费用与缺失样本。
- 每条近期明细保留 `eval_status`、周期、引擎、持仓方向、相同日线同时触价及评估时间，不能将行情不足当失败交易。
- `methodology.replay_validation` 明确标记“本次只读工具没有重新重放”。输出 `observational` 只表示存在历史完成记录，不代表已经通过当前实现、样本外或实盘验证。
- `get_skill_backtest_summary` 继续对没有真实技能回测汇总的情况返回 `supported=false`，不拿整体/个股结果替代技能表现。独立观点的 1/3/5/10 日方向结果也不等于长期价值回测或交易收益。

## 优化技能时的使用原则

1. 价格行为和 VCP 核对入场确认、结构失效、收益风险比与可执行时点。不能从这份历史分析语料拟合“最佳”均线、阈值或仓位。
2. 价值投资保留 3–5 年现金创造与论点证伪框架；10 日回测只能提供短期路径风险的背景，不能验证护城河、长期内在价值或配置胜率。
3. 日内做 T 和期权策略不得借用日线股票样本声称执行收益已验证；需要相应频率的行情、价差、费用、滑点和期权路径。
4. 多策略综合不把同一批价格数据的多个衍生信号当成独立成功证据；样本缺失不提高置信度或仓位。
5. 后续应积累带技能版本、信号时间、数据截至时间和评估周期的真实前向样本。按预先指定规则做时间外验证，保留失败和无法评估记录，再讨论策略间绩效差异。

当前模拟以解析后的日线锚点收盘价入场，不代表信号产生后能成交到该价格；同日止损与止盈均被触及时保守按止损先发生，但仍未建模跳空成交、买卖价差、手续费、滑点和资金占用。相互重叠的同股/同日窗口不是独立交易，也不能相加为组合收益或年化收益。

## 复现与验证

从仓库根目录执行（Python 环境需安装项目依赖）：

```bash
python scripts/audit_backtest_evidence.py --database data/stock_analysis.db
python scripts/audit_backtest_evidence.py --database data/stock_analysis.db --replay
python -m pytest tests/test_backtest_tool_evidence.py tests/test_backtest_service.py tests/test_backtest_engine.py tests/test_backtest_summary.py
```

数据库路径由参数指定。脚本直接使用 SQLite URI 的 `mode=ro`，不调用会执行迁移的 `DatabaseManager`，无联网补数据路径。`--replay` 的汇总按实际交易日窗口分组；审计时间、存量评估时间、差异类别与前 10 个差异记录标识均在 JSON 输出中。未提供批量覆盖或提交功能。

本次新增测试使用真实临时 SQLite 跑工具、服务与仓储联动，覆盖默认/显式周期、无汇总、空样本、错误周期、现金与不足样本排除、负期望及只读保护。原库读取与全量重放已实际执行。未做新技能的样本外收益验证；没有发布“优化后胜率”。
